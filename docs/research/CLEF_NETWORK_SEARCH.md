# Let Clef label first, route search second

WRLD should start Clef with article categorization, not with the search hot path: a Workflow-driven labeler that sends each wrld.tech blog post to `@cf/cloudflare/clef` (the 27B model) as one request carrying a Choice over the 19 categories already in front matter plus an `other` option and a battery of per-tag Nouls, stores the raw probabilities in D1, and projects the winning labels into the `wrld_section` and `wrld_kind` `<meta>` tags that the AI Search guideline already reserves. That pilot costs about **$0.18 for the full 304-post corpus** at the published $0.24 per million input tokens, fits inside the 10,000 free Neurons a day, runs offline where launch-week latency variance does not matter, and produces the labeled, threshold-validated dataset that the repo's existing `CLAUDE.md` guardrails require before any judgment touches a user. For network-wide search, the Clef-free work comes first: `wrld.design` is still missing from the namespace's authorized hosts, the `wereallylovedesign` instance rejects hybrid retrieval, the live endpoint ignores `instance_ids` narrowing, and no property emits a single `wrld_*` tag, so per-property scoping has to be a metadata filter fed by the categorization output. Once those account-level fixes land and a federation Worker exists, the second phase adds `clef-flash` as a speculative router (intent, target site, answer-or-links, off-topic) fired in parallel with the AI Search fan-out at roughly **$0.18 per thousand queries** against AI Search's $0.75 per thousand semantic queries; Clef as a relevance gate on retrieved chunks is a third phase to justify with measurement, not a starting point. Every accuracy and latency headline is Cloudflare's own; the independent record is one week old and shows Clef at 0.5 to 0.7 s end-to-end over REST, well calibrated on intent classification, weak on ordered scores and "should I act" gates, and carrying a `confidence` field whose formula differs from Jev's, so thresholds must be computed in code from the returned probabilities.

## Clef returns calibrated probabilities over 64 typed questions, billed only on input

Clef and Clef-flash shipped on Workers AI on 2026-10-01 as decision models "in the same family as Typesafe's Jev": a request is `{ model, state, questions }` where `state` is a string or any JSON value and `questions` is a map of **1 to 64 typed questions** of type `noul`, `choice` or `score`; the response carries one answer per question id with the full per-option `probabilities`, plus `usage` ([Cloudflare changelog](https://developers.cloudflare.com/changelog/post/2026-10-01-clef-workers-ai/); [Clef input schema](https://developers.cloudflare.com/workers-ai/models/clef/schema-input.json); [Clef output schema](https://developers.cloudflare.com/workers-ai/models/clef/schema-output.json)). Clef (27B, post-trained from Qwen3.8-27B) is priced at **$0.24 per million input tokens** and Clef-flash (9B, Qwen3.5-9B) at **$0.09**, both with a **65,536-token context** and vision through up to four embedded base64 images; remote image URLs are rejected and long text state is silently truncated rather than refused ([Clef model page](https://developers.cloudflare.com/workers-ai/models/clef/); [Clef-flash model page](https://developers.cloudflare.com/workers-ai/models/clef-flash/); [Hugging Face Cloudflare/clef](https://huggingface.co/Cloudflare/clef)). No output price is listed on either page, the published reference code hard-codes `output_tokens: 0`, and every observed hosted response reported zero output tokens, so input is the whole bill ([joint_schema_model.py](https://huggingface.co/Cloudflare/clef/raw/main/joint_schema_model.py); [Flavio Copes](https://flaviocopes.com/clef/)).

Workers AI meters everything as Neurons at **$0.011 per 1,000 with 10,000 free per day** ([Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/)); converting the dollar rates gives roughly 21,800 Neurons per million Clef tokens, so the daily free allowance covers about **458,000 Clef or 1.22 million Clef-flash input tokens**, a derivation from the published rates rather than a Cloudflare figure, since the pricing page's per-model table has no Clef row. Both model pages file the variants under Text Generation, whose default limit is **300 requests per minute**, and neither flags a Workers Paid requirement, so that default is the working assumption ([Workers AI limits](https://developers.cloudflare.com/workers-ai/platform/limits/)). Clef is absent from the asynchronous Batch API's published model list, which means batching happens inside a request (up to 64 questions over one state), not across requests ([Cloudflare changelog 2025-04-11](https://developers.cloudflare.com/changelog/post/2025-04-11-new-models-faster-inference/)). Invocation is `env.AI.run("@cf/cloudflare/clef", {...})` from a Worker binding, which returns the bare object, or `POST .../ai/run/@cf/cloudflare/clef` over REST, which wraps the body in Cloudflare's `result` envelope; either path accepts an AI Gateway option (`{ gateway: { id, skipCache, cacheTtl } }`) for logging and caching ([Clef model page](https://developers.cloudflare.com/workers-ai/models/clef/); [AI Gateway Workers AI provider page](https://developers.cloudflare.com/ai-gateway/usage/providers/workersai/); [Classmethod DevelopersIO](https://dev.classmethod.jp/en/articles/cloudflare-clef-overview/)). Two launch-week sharp edges: `wrangler types` did not include Clef, so `answers` came back typed `unknown`, and sending `"model": "jev-latest"` fails with error 5006 ([Flavio Copes](https://flaviocopes.com/clef/)).

The TypeSafe guidance WRLD adopted in PR #32 transfers almost verbatim. `CLAUDE.md` already fixes the shape of a judgment (Noul, Choice, Score), requires a no-match outcome on every Choice, and sets five guardrails: judgments inform and people decide, confidence is distribution concentration not permission, raw judgments are stored and policy lives in code, credentials never reach a browser, and nothing runs inside the published design-system artifact ([CLAUDE.md](../../CLAUDE.md)). Cloudflare's claim that "you can switch an existing Jev integration to Clef by changing the endpoint and model" was independently confirmed with the one addition of unwrapping `result` on REST ([Cloudflare changelog](https://developers.cloudflare.com/changelog/post/2026-10-01-clef-workers-ai/); [Classmethod DevelopersIO](https://dev.classmethod.jp/en/articles/cloudflare-clef-overview/)). The trap is `confidence`. TypeSafe defines Choice confidence as `(p_max − 1/n) / (1 − 1/n)`, whereas Cloudflare's published helper sets it to the winning option's probability, so options at 0.80/0.15/0.05 score **0.70 under Jev's formula and 0.80 under Clef's code**, and an existing `>= 0.75` rule would flip between providers ([TypeSafe Confidence](https://docs.typesafe.ai/confidence.md); [Wavect](https://wavect.io/blog/cloudflare-clef-vs-jev/)). Whether the hosted endpoint uses that exact revision is unverified, and an independent benchmark reached the same operational conclusion: "Do not port a `confidence` threshold between them" ([Requesty](https://www.requesty.ai/blog/decision-model-benchmark-clef-sference-cloudflare-perplexity)). The fix is cheap because every answer returns its full distribution: a thin adapter recomputes confidence from `probabilities` with one chosen formula, which also makes WRLD's thresholds provider-independent. One more logging gap: the published code echoes the request's `model` value rather than a versioned build id, unlike Jev's `jev-1.13.0`, so each stored judgment needs an external version note ([joint_schema_model.py](https://huggingface.co/Cloudflare/clef/raw/main/joint_schema_model.py); [TypeSafe Models](https://docs.typesafe.ai/models.md)).

## Network-wide search: fix the namespace before Clef touches a query

`search.wrld.ai` is a namespace public endpoint over namespace `default` in the WRLD Inc. account, fanning each `/search`, `/chat/completions` and `/mcp` call across two allow-listed instances, `wereallylovedesign` (wrld.tech sitemap, vector only, `@cf/qwen/qwen3-embedding-0.6b`) and `wrld-search` (help.wrld.tech, hybrid with reranking and query rewrite), with `instances_allowed` capped at 10 and `public_endpoint_params` replaced in full on every `PUT` ([AI_SEARCH_AGENTS.md §2](../../docs/AI_SEARCH_AGENTS.md); [Namespace public endpoints](https://developers.cloudflare.com/ai-search/configuration/retrieval/public-endpoint/namespace/)). This is exactly the topology Cloudflare runs for itself: the Dev Stack MCP uses ten instances in one namespace and a Worker bound with `ai_search_namespaces` that makes a single `env.AI_SEARCH.search({ ai_search_options: { instance_ids, reranking: { enabled: true } } })` call, with the public namespace endpoint as the no-code fallback ([Cloudflare AI Search blog, 2026-08-06](https://blog.cloudflare.com/ai-search-easier/)). AI Search went GA on 2026-10-01 with **billing starting 2026-11-01**; each account includes 1,000 semantic and 1,000 full-text queries a month, then **$0.75 per 1,000 semantic queries** and $0.10 per 1,000 full-text, with managed embedding and reranking included in that price ([AI Search limits and pricing](https://developers.cloudflare.com/ai-search/platform/limits-pricing/); [AI Search GA blog](https://blog.cloudflare.com/ai-search-ga/)). The docs do not say whether a cross-instance fan-out bills as one query or N, which matters for the search budget once the namespace holds five instances.

Three live probes on 2026-10-08 change the design more than any vendor page. First, `OPTIONS https://search.wrld.ai/search` with `Origin: https://wrld.design` returns no `Access-Control-Allow-Origin`, while `wrld.tech` does; the §3.3 open item from 2026-09-30 is still open and the apex overlay still shows its unavailable state ([search.wrld.ai](https://search.wrld.ai/search); [CHANGELOG.md](../../docs/CHANGELOG.md)). Second, a hybrid request against `wereallylovedesign` returns `retrieval_type 'hybrid' is not available: keyword indexing is disabled in index_method`, so wrld.tech content, including all 304 blog posts, is searchable by vector only; enabling hybrid means changing `index_method` to `{ vector: true, keyword: true }`, which triggers a full reindex and halves the Paid file cap from 1M to 500K, and because renaming an instance means recreating it, the clean move is to recreate it as `wrld-tech-site` under the guideline's naming rule ([search.wrld.ai](https://search.wrld.ai/search); [Hybrid search](https://developers.cloudflare.com/ai-search/configuration/indexing/hybrid-search/); [AI_SEARCH_AGENTS.md §3.2](../../docs/AI_SEARCH_AGENTS.md)). Third, narrowing with `ai_search_options.instance_ids` to one instance returned chunks from the other in three separate probes, although Cloudflare documents that field as the narrowing mechanism; the registry dialog's `instanceIds` prop and the agent skeleton's per-property routing both assume it works ([search.wrld.ai](https://search.wrld.ai/search); [wrld-search-dialog.tsx](../../registry/blocks/wrld-search-dialog.tsx)). The consequence is structural: **per-property and per-category scoping must be a metadata filter**, and filters need the `<meta wrld_*>` tags that no property emits today, which is why categorization output is a prerequisite for search rather than a separate project. AI Search filters apply before retrieval, allow at most five custom fields per instance, index only the first 64 UTF-8 bytes of a string, and cannot filter arrays ([Filtering](https://developers.cloudflare.com/ai-search/configuration/retrieval/filtering/); [Metadata attributes](https://developers.cloudflare.com/ai-search/configuration/indexing/metadata/)).

| Option | Shape | Pros | Cons |
| --- | --- | --- | --- |
| **S1. AI Search-native federation, no Clef** | Extend `instances_allowed` to one instance per property; recreate wrld.tech as hybrid; enable reranking, similarity cache and `wrld_*` filters; set the endpoint rate limit; keep `search.wrld.ai` for snippets and `/mcp` | Zero new code; matches Cloudflare's own production config (hybrid everywhere); reranker and cache included in the query price; every blocker is an account toggle; fixes the four live defects | No intent awareness; cannot choose answer-card versus link-list; no abuse or off-topic gate; relies on `wrld_*` tags that do not exist yet |
| **S2. Federation Worker with a Clef-flash speculative router** | A Worker bound to the namespace (`remote: true`) fires `clef-flash` and `env.AI_SEARCH.search()` concurrently; one call asks `target_site`, `intent`, `needs_generated_answer`, `is_followup`, `off_topic_or_abuse`, `urgency`; code re-weights results by `instance_id` and `scoring_details` and gates `/chat/completions` | Adds no user-visible latency when run in parallel (vendor median 38.8 ms, independent 191 to 205 ms); about $0.18 per 1,000 queries; the Worker also solves credential handling and per-site weighting; AI Gateway exact-match cache skips Clef on repeated queries | First WRLD Worker to carry an `ai_search_namespaces` binding in production, so every build needs `CLOUDFLARE_API_TOKEN`; Clef-flash collapses on out-of-scope detection (CLINC150+OOS 66.8 vs 97.4); thresholds unvalidated until the categorization pilot produces data |
| **S3. Clef as relevance gate or reranker on retrieved chunks** | After retrieval, one Clef call with the query plus up to 50 candidates and one Noul per candidate; drop low-evidence chunks before generation; optionally one request per query-candidate pair | TypeSafe's cookbook lifted top-10 accuracy from 38% to 62% on hard legal queries; filters planted prompt-injection passages that cosine similarity ranked first; same probabilities re-usable under new policies | Serial latency after retrieval (Clef 0.5 to 0.7 s median over REST, up to 3 s); cost scales with candidates; Jev beats Clef on reasoning-intensive retrieval (BRIGHT 47.5 vs 45.9, vendor); AI Search's included cross-encoder reranker already covers the cheap case; decision models scored 4/12 on embedded-instruction attacks, so it is a filter, not a security boundary |

S1 is not a lesser option; it is the one Cloudflare itself ships, and its pieces are already paid for. Reranking with `@cf/baai/bge-reranker-base` is a per-request flag whose Workers AI usage is included in AI Search pricing, the similarity cache keys on MinHash with a 48-hour default TTL and purges when source chunks change, relevance boosting can re-score up to 50 candidates on three metadata fields, and the public endpoint's rate limit defaults to 120 requests per minute with a fixed window, a limit WRLD's namespace still has unset ([Reranking](https://developers.cloudflare.com/ai-search/configuration/retrieval/reranking/); [Similarity cache](https://developers.cloudflare.com/ai-search/configuration/retrieval/cache/); [Relevance boosting](https://developers.cloudflare.com/ai-search/configuration/retrieval/boosting/); [Public endpoint settings](https://developers.cloudflare.com/ai-search/configuration/retrieval/public-endpoint/); [AI_SEARCH_AGENTS.md §2](../../docs/AI_SEARCH_AGENTS.md)). Two guardrails apply to any gateway wiring: never enable AI Gateway response caching or rate limiting on the gateway attached to the AI Search instances, because cached embeddings can return wrong vectors and throttling would starve indexing, so Clef calls belong on a second gateway with caching on ([AI Search > AI Gateway](https://developers.cloudflare.com/ai-search/configuration/models/ai-gateway/); [AI Gateway caching](https://developers.cloudflare.com/ai-gateway/features/caching/)).

S2's economics hold because the search call is the long pole: at roughly 2,000 input tokens per router call (query, instructions, a dozen snippets), Clef-flash costs about $0.00018 per query, or $0.18 per thousand, versus $0.75 per thousand semantic queries on AI Search, both derived from the published rates ([Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/); [AI Search limits and pricing](https://developers.cloudflare.com/ai-search/platform/limits-pricing/)). The question design follows TypeSafe's intent-routing and speculative fan-out patterns: ask every question the code might need in one call, keep the intent Choice to five to seven options with an explicit `other`, and route below a confidence floor to the plain link list rather than to generation ([TypeSafe Primitives](https://docs.typesafe.ai/primitives.md); [TypeSafe intent routing](https://docs.typesafe.ai/patterns/intent-routing.md)). The vendor's own numbers warn where Clef-flash should not decide alone: on CLINC150 with an out-of-scope class it scores **66.8 macro-F1 against Clef's 97.4**, so the off-topic question is a candidate for full Clef if measurement shows the small model missing it ([Hugging Face Cloudflare/clef](https://huggingface.co/Cloudflare/clef)). Use `target_site` to re-weight and group merged results, and only narrow `instance_ids` when confidence is high, because pre-retrieval narrowing trades recall for precision and, on the live endpoint today, does nothing at all.

## Article categorization: a Workflow-driven labeler beats build scripts and embeddings

The categorization substrate already exists on wrld.tech: all 304 Markdown posts carry `categories`, `categoryNames`, `tags` and a `wpId` from the WordPress import, with 19 category names in use (Cybersecurity 138, IT Management 42, Productivity 39, Microsoft 35, Business 33, New Technology 28, and so on), but **only 40 posts carry any tag and 273 of 304 are syndicated third-party content** with an external `canonical` ([blog directory](https://github.com/WRLDInc/WeReallyLoveDesign/tree/main/site/src/content/blog/); [content.config.ts](https://github.com/WRLDInc/WeReallyLoveDesign/blob/main/site/content.config.ts)). help.wrld.tech holds 38 MDX pages and wrld.design 38 sitemap URLs, neither with labels beyond navigation ([docs.json](https://github.com/WRLDInc/docs/blob/main/docs.json); [wrld.design llms.txt](https://wrld.design/llms.txt)). The job is therefore less about inventing a taxonomy than about filling the empty tag field, validating the inherited categories, and emitting the five-field `wrld_*` schema that search can filter on.

| Option | Shape | Pros | Cons |
| --- | --- | --- | --- |
| **C1. Workflow-driven Clef labeler with D1 as the canonical store** | A dedicated Worker: one Workflow instance per article with a deterministic id (`site:slug:contentHash:taxonomyVersion`); steps fetch and normalize to JSON, store raw content in R2, call `@cf/cloudflare/clef` through AI Gateway, write one D1 row per (article, taxonomy version, model, question, option, probability), then enqueue write-backs; thresholds live in a `label_policy` table | Durable retries and idempotency; raw probabilities stored so a policy change is a query, not a re-run; AI Gateway logs accumulate the dataset Cloudflare's fine-tuning service consumes; same pipeline reusable for ticket triage and lead scoring; keeps Clef out of the static artifact as `CLAUDE.md` demands | New ground for WRLD (no property declares Workflows or Queues bindings today); Workflow id dedup is undocumented and needs a test; D1 is single-threaded per database so backfills must batch writes |
| **C2. Question design is the part TypeSafe has already written for WRLD. A Choice "fits when the answer is one of a known set of options with no order between them", the full option list should be given (up to 255, "reliably up to roughly 240"), and "add an `other` or `none of the above` option when the list might not cover every input" ([TypeSafe Primitives](https://docs.typesafe.ai/primitives.md); [TypeSafe Choice](https://docs.typesafe.ai/primitives/choice.md); [TypeSafe classification cookbook](https://docs.typesafe.ai/cookbooks/classification_using_confidence.md)). So the per-article request is one Choice `primary_category` over the 19 names plus `other`, one Noul per tag slug for multi-label tags, Nouls for housekeeping checks that need judgment (has a runnable code sample, written for a non-technical reader, mentions pricing), and a Choice for sub-brand attribution with its own `other`; code already knows `syndicated` from front matter, so that stays a code-side boost signal rather than a question. Ordered Scores for depth or quality should be the exception: an independent gateway benchmark found decision models "10 points weaker on ordered rubrics" and recommended Nouls wherever a binary framing exists ([Requesty](https://www.requesty.ai/blog/decision-model-benchmark-clef-sference-cloudflare-perplexity)). All independent questions go in one request, since batching 13 questions into one call was measured at 11.5x cheaper and 9.6x faster than 13 calls ([TypeSafe Primitives](https://docs.typesafe.ai/primitives.md)). The state should be a structured object (site, URL path, title, description, headings, excerpt, a bounded body slice, existing tags, author, date) with questions pointing at backticked field paths, because "accuracy falls as the state grows with content unrelated to the decision" ([TypeSafe Jev 1.13 jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md); [TypeSafe how to build](https://docs.typesafe.ai/concepts/how-to-build-with-system-one.md)). If the network tag vocabulary ever exceeds the 64-question cap, the hierarchical cookbook's two-level beam search (tag-group Choice first, then Nouls within winning groups) recovered the right leaf in 4 of 4 taxonomies against 2 of 4 for greedy ([TypeSafe hierarchical classification](https://docs.typesafe.ai/cookbooks/hierarchical_classification.md)).

The model choice is Clef, not Clef-flash, and the reason is the `other` outcome. In Cloudflare's own benchmark table Clef-flash scores **66.8 on CLINC150+OOS against Clef's 97.4** and 35.6 on RAGTruth hallucination detection against 79.4; out-of-scope recognition is exactly the signal that tells an editor a post fits no category ([Hugging Face Cloudflare/clef](https://huggingface.co/Cloudflare/clef)). Independent runs support Clef's strength on the closed-set part of the job: 94.3% on Banking77 and 89.3% on MASSIVE with expected calibration error of 0.02 to 0.04 on four of five datasets ([Requesty](https://www.requesty.ai/blog/decision-model-benchmark-clef-sference-cloudflare-perplexity)), and 150 of 167 agreements with reference labels against 138 for Clef-flash, which was also "confidently wrong more often" ([Startrise](https://www.startrise.io/blog/jev-vs-clef/)). The honest counterweight is a pre-registered study of Jev against 19 LLMs on 18 annotation tasks: the decision model trailed the best LLM on 14 of 15 tasks by a median 11.6 macro-F1 points at 44 times lower cost, but cascades that keep confident items on the decision model and escalate the rest matched the LLM alone at a quarter to half its cost ([arXiv 2609.24574](https://arxiv.org/html/2609.24574)). That is the architecture: Clef first, a person (or a larger model) for the low-confidence band.

Thresholds must come from WRLD's own labels on held-out data. The same audit literature found in-sample thresholds with a 5% miss target producing up to 17% held-out misses ([arXiv 2610.02267](https://arxiv.org/abs/2610.02267)). TypeSafe's cookbooks give the operating shape: at a 0.9 cutoff the confident half of their filings was right 90% of the time and the other half 40%, and an explicit `uncertain` outcome below 0.60 raised label agreement across repeated runs to 99.2% while auto-labelling 74.2% ([TypeSafe classification cookbook](https://docs.typesafe.ai/cookbooks/classification_using_confidence.md); [TypeSafe self-consistency cookbook](https://docs.typesafe.ai/cookbooks/consistency_choice_cookbook.md)). A sensible first policy is auto-apply at recomputed confidence of 0.9 or more, fall back to the site's general bucket between 0.6 and 0.9, and queue for review below 0.6 or whenever `other` carries more than about a quarter of the mass; the reviewer's corrections flow back into D1 as gold labels, which both measures drift and seeds a future fine-tune. Clef's determinism helps here: identical inputs produced identical outputs across five runs where Jev alternated, though that is observed behaviour rather than a documented guarantee ([Classmethod DevelopersIO](https://dev.classmethod.jp/en/articles/cloudflare-clef-overview/)).

Write-back is where the platform limits bite. AI Search reads custom metadata from `<meta name|property>` tags in `<head>`, allows five custom fields per instance, filters only scalars, and treats a schema change as a full reindex ([Website custom metadata](https://developers.cloudflare.com/ai-search/configuration/data-source/website/custom-metadata/); [Metadata attributes](https://developers.cloudflare.com/ai-search/configuration/indexing/metadata/)). WRLD's guideline has already spent that budget on `wrld_property`, `wrld_section`, `wrld_audience`, `wrld_updated` and `wrld_kind`, and says plainly "do not add a sixth for one site" ([AI_SEARCH_AGENTS.md §7.2](../../docs/AI_SEARCH_AGENTS.md)). The primary category therefore maps to `wrld_section` and the content type to `wrld_kind`; multi-label tags cannot be filtered in AI Search at all and should live in D1 (and, if a custom search path ever needs them, in Vectorize's ten scalar metadata indexes). For Astro sites the clean projection is a custom content loader that merges labels from the labeler's API at build time, with `z.enum` over the taxonomy so a drifted label fails the build ([Astro content collections](https://docs.astro.build/en/guides/content-collections/)); Mintlify exposes only a single `tag` string plus `keywords` for search ([Mintlify Pages](https://www.mintlify.com/docs/organize/pages)); WordPress, relevant to WRLD.Press clients, accepts `categories`, `tags` and registered `meta` on `POST /wp/v2/posts/<id>` ([WordPress REST API Posts](https://developer.wordpress.org/rest-api/reference/posts/)). After a write-back, a sync can be triggered from CI at most once every 30 seconds via `npx wrangler ai-search jobs create` ([Syncing](https://developers.cloudflare.com/ai-search/configuration/indexing/syncing/)).

The pipeline's surrounding limits are generous at WRLD's scale. Workflows allow 30 s of CPU per step (configurable to 5 minutes), a 1 MiB step result (so large probability maps are written to D1 inside the step, not returned), 100 instance creations per second per workflow, and bill 500,000 steps a month before $0.80 per additional 100,000, with step billing live since 2026-08-10 ([Workflows limits](https://developers.cloudflare.com/workflows/reference/limits/); [Workflows pricing](https://developers.cloudflare.com/workflows/reference/pricing/)). Queues carry 128 KB messages in batches of up to 100 with explicit per-message acknowledgement for non-idempotent write-backs, and include one million operations a month before $0.40 per million ([Queues limits](https://developers.cloudflare.com/queues/platform/limits/); [Queues batching and retries](https://developers.cloudflare.com/queues/configuration/batching-retries/); [Queues pricing](https://developers.cloudflare.com/queues/platform/pricing/)). D1 includes 25 billion rows read and 50 million written a month but processes queries one at a time per database, so backfills should write in batches of about 1,000 rows ([D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/); [D1 limits](https://developers.cloudflare.com/d1/platform/limits/)). At the 300-requests-per-minute default, 10,000 articles backfill in about 34 minutes; WRLD's 304 posts take about a minute.

## Start with the 304-post blog backfill, then run Clef-flash beside the fan-out

The recommended starting point is **C1 on the wrld.tech blog, with S1 running in parallel as account-level work**, then S2, then S3 only on evidence. Four reasons favour categorization as the first Clef workload. It is offline, so the launch-week latency picture, Clef at 524 to 726 ms median over REST with single calls up to 3 s and image requests at 13 to 30 s, is irrelevant ([Flavio Copes](https://flaviocopes.com/clef/)). It is nearly free: 304 posts at a standard 2,500-token payload is about 760,000 input tokens, roughly **$0.18 on Clef** at the published rate and inside the derived 458,000-token daily free allowance over two days, with steady-state publishing at 500 posts a month costing about $0.30 ([Clef model page](https://developers.cloudflare.com/workers-ai/models/clef/); [Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/)). It is the prerequisite for scoped search, because `instance_ids` narrowing is not honoured on the live endpoint and filters need tags that only this pipeline will produce ([search.wrld.ai](https://search.wrld.ai/search)). And it is the only way to satisfy the guardrail already on file: "Validate thresholds on real WRLD surfaces before relying on them, and send low-confidence or failing cases to a person" ([CLAUDE.md](../../CLAUDE.md)). The labeled sample the pilot produces is the evaluation harness every later Clef use inherits.

Phase zero is a short list of account changes reserved for @Ridgelawrence: append `wrld.design` (and each exact preview hostname, since wildcards do not match on the preflight) to `authorized_hosts` with the read-append-write call in §3.3; set the namespace endpoint rate limit to 120 per minute fixed; replace the MCP tool description, which the live `tools/list` still reports as Cloudflare's default "Finds exactly what you're looking for"; and decide whether to recreate `wereallylovedesign` as `wrld-tech-site` with hybrid indexing ([AI_SEARCH_AGENTS.md §3.3 and §8](../../docs/AI_SEARCH_AGENTS.md); [search.wrld.ai/mcp](https://search.wrld.ai/mcp)). Phase one is the labeler Worker: declare `ai`, `d1_databases`, `workflows`, `r2_buckets` and `queues` bindings in `wrangler.jsonc` rather than the dashboard, because dashboard-only bindings stopped wrld.tech's deploys on 2026-09-19 ([AI_SEARCH.md](https://github.com/WRLDInc/WeReallyLoveDesign/blob/main/docs/AI_SEARCH.md)); route Clef through a dedicated AI Gateway so a request dataset accumulates from day one, which is the input Cloudflare's RL fine-tuning pipeline is built to consume ([Cloudflare launch blog](https://blog.cloudflare.com/clef-decision-models/)); log `usage.input_tokens` per article to replace the 2,500-token assumption with measured averages; have two editors label a stratified sample (the research suggests 200 to 300 per site, which for a 304-post corpus is most of it), choose thresholds on a held-out half, and record coverage alongside accuracy. Then emit `wrld_section` and `wrld_kind` on wrld.tech's `Base.astro` through a content loader, trigger a sync, and verify that a filtered `/search` returns only the expected property.

Phase two builds the federation Worker (S2) once labels exist: bind the namespace with `remote: true` and provide `CLOUDFLARE_API_TOKEN` to every build environment, fire `clef-flash` concurrently with `env.AI_SEARCH.search()` with reranking on, apply `wrld_section` filters and `boost_by` on `wrld_updated`, and use `metadata_only: true` for type-ahead ([AI_SEARCH_AGENTS.md §4.1](../../docs/AI_SEARCH_AGENTS.md); [Workers binding](https://developers.cloudflare.com/ai-search/api/search/workers-binding/)). Keep `search.wrld.ai` as the public endpoint for the pinned v0.0.40 snippets and `/mcp`, so nothing changes for wrld.design's overlay or the committed `.mcp.json` files. Phase three, the Clef relevance gate, is justified only if the Worker's logs show generated answers citing low-evidence chunks at a rate that the included cross-encoder reranker does not fix. One governance note belongs on the record before phase one starts: `CLAUDE.md` scopes TypeSafe to "a review and triage tool around" the design system, so classifying public content and steering public search is a scope extension that needs Ridgeway's sign-off and a one-line amendment, with @cowboyspice looped in for the Craft page that §8.1 step 9 requires.

Clef and AI Search carry their own unverified edges. On the model side: the hosted `confidence` formula, whether the response `model` field carries a version, image token metering, Batch API eligibility, and any SLA or data-residency statement are all undocumented, and text state truncates silently at the context limit ([Clef input schema](https://developers.cloudflare.com/workers-ai/models/clef/schema-input.json); [Wavect](https://wavect.io/blog/cloudflare-clef-vs-jev/)). On the search side: whether a cross-instance fan-out bills as one query or N, how metadata filters behave across instances with different schemas, whether a Workers route can intercept the custom-domain hostname, and the keyword engine that Cloudflare says it is still "refactor[ing] so that it scales better" ([AI Search GA blog](https://blog.cloudflare.com/ai-search-ga/)). The design above sidesteps each: filters over a uniform `wrld_*` schema, a federation Worker on its own hostname, and raw-probability storage that makes a confidence-formula change a query rather than a re-run.

The price story deserves the same separation. Clef is **5.7 times Jev's $0.042 per million input tokens**, and a million 2,000-token decisions cost about $84 on Jev, $180 on Clef-flash and $480 on Clef by one independent arithmetic ([TypeSafe Models](https://docs.typesafe.ai/models.md); [Wavect](https://wavect.io/blog/cloudflare-clef-vs-jev/)); an 8B instruct model in JSON mode is cheaper per article still. Clef's case for WRLD therefore rests on the Workers-native binding with no key to rotate, AI Gateway logging on the same account, structured probabilities with no refusals or format failures ("0 unusable answers in 4,000" in one run), and 64 parallel questions per call, not on the lowest bill ([Requesty](https://www.requesty.ai/blog/decision-model-benchmark-clef-sference-cloudflare-perplexity)). At WRLD's volumes the difference is cents a month either way, which is why the operational fit, not the token price, should decide.

## Conclusion

The research reframes the question. Clef is not a search engine and should not be asked to become one; AI Search already retrieves, fuses, reranks and caches for a price that includes those steps, and Cloudflare runs its own blog and docs that way. Clef's distinctive contribution is a cheap, calibrated, 64-question judgment over a state WRLD controls, and the first state worth judging is the blog corpus, because labelling it simultaneously fills an empty tag field, produces the metadata that scoped search needs now that `instance_ids` cannot be trusted, and generates the held-out evaluation set without which no confidence threshold is defensible. The categorization pilot is therefore the evaluation harness, the metadata feed and the first production Clef workload in one, for less than a dollar.

Two design decisions will outlast the model choice. Storing raw probabilities keyed by taxonomy and model version, and recomputing confidence in code, makes WRLD indifferent to whether the hosted formula matches the published one, to a future switch back to Jev, and to the self-serve fine-tuning Cloudflare has promised but not shipped. And keeping one AI Search instance per property in one namespace, with a uniform five-field `wrld_*` schema, is the shape most likely to survive Cloudflare's stated direction toward per-domain AI indexes; everything the estate still lacks to get there is an account toggle, not a rewrite.
